1. Аутентификация
1.1. Логин
POST /auth/login/

Тело:

JSON

{
  "login": "driver1",
  "password": "12345",
  "client": "web"   // "web" или "mobile"
}
Ответ:

JSON

{
  "access": "<JWT>",
  "user": {
    "id": 5,
    "login": "driver1",
    "role": 3,
    "name": "Иван",
    "surname": "Иванов",
    "last_name": "Иванович"
  }
}
В токене в payload есть:

JSON

{
  "sub": 5,
  "login": "driver1",
  "role": 3,
  "client": "mobile",      // то, что было в login.client
  "pwd_fp": "<отпечаток_пароля>",
  "iat": ...,
  "exp": ...
}
Если пароль пользователя изменится, все старые токены станут невалидными.

2. Модель прав
2.1. Роли
/roles/ — CRUD ролей (name).

2.2. Permission (права роли)
/permissions/ — CRUD прав для роли.

Основные флаги, важные для фронта:

view_passenger_cars_waybills — просмотр путевых легковых.

can_create_passenger_cars_waybills — создание шапки путевого (легковой).

can_update_passenger_cars_waybills, can_delete_passenger_cars_waybills.

can_download_passenger_cars_waybills — выгрузка отчёта Excel (легковой).

can_create_passenger_cars_waybills_record — создание записей (record) с WEB (легковой).

can_update_passenger_cars_waybills_record, can_delete_passenger_cars_waybills_record.

Аналогичные флаги для пожарных:
view_fire_truck_waybills, can_create_fire_truck_waybills,
can_download_fire_truck_waybills,
can_create_fire_truck_waybills_record и т.д.

can_use_mobile_booking — право создавать записи с мобильного приложения.

Правило:

Запрос с client="web" → для создания записей проверяется can_create_*_waybills_record.
Запрос с client="mobile" → для создания записей проверяется can_use_mobile_booking.
Если оба флага у роли = True → пользователь может создавать записи и с веба, и с мобилки.

3. Легковой автомобиль
3.1. Машины
/passenger-cars/ — CRUD.

3.2. Нормы расхода
/passenger-car-norms/ — CRUD.

Доп. роут:

GET /passenger-car-norms/for-date/?car=<id>&season=<summer|winter>&date=YYYY-MM-DD

→ возвращает запись нормы для машины и сезона, действующую на дату документа (последнюю по date <= указанной).

3.3. Снимки одометра/топлива
/passenger-car-odometer-fuel/ — CRUD.

GET /passenger-car-odometer-fuel/last/?car=<id> → последний снимок по машине.

Используется на бэке для:

определения odometer_before / fuel_before_departure перед новой записью;
создания нового снимка после записи (odometer_after / fuel_on_return).
3.4. Путевой — шапка
Ресурс: /passenger-car-waybills/

Доступ по правам:

update, partial_update → can_update_passenger_cars_waybills.

3.5. Путевой — строки (записи)
Ресурс: /passenger-car-records/

Права:

list, retrieve → view_passenger_cars_waybills.
create → зависит от client в JWT:
client="web" → нужно can_create_passenger_cars_waybills_record.
client="mobile" → нужно can_use_mobile_booking.
update, partial_update → can_update_passenger_cars_waybills_record.
destroy → can_delete_passenger_cars_waybills_record.

5. Кратко по сценариям использования
Водитель через мобильное
Логин с client="mobile".
В Permission роли водителя:
can_use_mobile_booking = True,
view_*_waybills = True (для чтения),
can_create_*_waybills_record можно не ставить (если создавать записи ТОЛЬКО с мобилки).
Тогда:

GET /api/passenger-car-waybills/ — если есть view_passenger_cars_waybills.
POST /api/passenger-car-records/ → разрешено, потому что client="mobile" и can_use_mobile_booking=True.
Механик через веб
Логин с client="web".
В Permission механика:
can_create_passenger_cars_waybills = True,
can_create_passenger_cars_waybills_record = True,
can_use_mobile_booking может быть False.
Тогда:

может создавать шапки и записи через веб;
не может создавать записи с мобилки (если can_use_mobile_booking=False).
