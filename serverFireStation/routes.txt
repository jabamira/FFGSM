1. Общие правила
Формат данных
Все обычные ответы — JSON.
Excel‑отчёты — бинарный .xlsx файл.
Даты передавать в формате:
text

YYYY-MM-DD
пример:

text

2025-01-31
Время:
text

HH:MM:SS
пример:

text

08:30:00
Decimal‑поля обычно приходят как строки:
JSON

"fuel": "12.500"
Авторизация
Почти все роуты требуют JWT:

http

Authorization: Bearer <TOKEN>
Если токен не передан / неверный / просрочен → 401.

2. Авторизация (JWT)
2.1. Вход в систему
POST /api/auth/login/
Тело запроса:
JSON

{
  "login": "driver1",
  "password": "12345",
  "client": "web"
}
или для мобильного приложения:

JSON

{
  "login": "driver1",
  "password": "12345",
  "client": "mobile"
}
Ответ:
JSON

{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....",
  "user": {
    "id": 5,
    "login": "driver1",
    "role": 3,
    "name": "Иван",
    "surname": "Иванов",
    "last_name": "Иванович"
  }
}
Что делать на фронте:
сохранить access;
во все последующие запросы добавлять:
http

Authorization: Bearer <access>
2.2. Проверка токена / текущий пользователь
GET /api/auth/me/
Заголовки:
http

Authorization: Bearer <TOKEN>
Ответ:
JSON

{
  "id": 5,
  "name": "Иван",
  "surname": "Иванов",
  "last_name": "Иванович",
  "login": "driver1",
  "phone": "+79001234567",
  "driver_license": "1234567890",
  "role": 3,
  "deleted_at": null
}
Этот роут нужен, чтобы:

проверить, что токен ещё жив;
восстановить текущего пользователя после перезагрузки приложения.

10. Логика прав для создания записей с web/mobile
Для POST /api/passenger-car-records/ и POST /api/fire-truck-records/
Права зависят от client в JWT:

если client = "web":
нужен permission:
can_create_passenger_cars_waybills_record
или can_create_fire_truck_waybills_record
если client = "mobile":
нужен can_use_mobile_booking = true
То есть:

пользователь с правом создания record через web — может создавать только с web;
пользователь с can_use_mobile_booking = true — может создавать через mobile;
если у роли оба флага true, можно и так и так.
11. Что важно фронту
Read-only поля
Во многих документах сервер сам считает поля. Их не надо отправлять при POST/PUT/PATCH.

Например, в PassengerCarWaybillRecord не нужно отправлять:
fuel_before_departure
odometer_before
odometer_after
distance_total_km
fuel_used_city
fuel_used_area
fuel_on_return
fuel_used_normal
В FireTruckWaybillRecord не нужно отправлять:
fuel_before_departure
odometer_before
distance_km
fuel_on_return
fuel_used_by_distance
fuel_used_with_pump
fuel_used_without_pump
fuel_used_normal
В документах:
number — автонумерация, не передавать;
operating_hours в TechnicalMaintenance — тоже не передавать.
